Kenosis AI plugins

Kenosis AI ships without the Android INTERNET permission — Android itself blocks its network access. Plugins are separate apps that add optional abilities: the host discovers them on the same device and talks to them over a local binder — host–plugin IPC is binder, not a socket. LiveCast then serves only on your own Wi-Fi while a session runs.

Every plugin is open source and shows exactly what it does. Uninstall the plugin, and the host carries on fully offline.

How plugins work

One hard architecture rule: only the plugin apps — never the host — hold network access.

1

The host stays offline

Kenosis AI has no INTERNET permission. Android itself enforces the isolation — it works in airplane mode, forever.

2

A plugin binds locally

The host discovers a plugin app on the device and binds it over a local AIDL binder. The open contract is one small file, identical in both apps.

3

You see everything

A plugin is an app of its own with its own screen. Internet Search logs every URL it fetches; LiveCast shows the session and who is connected. Nothing is hidden.

Plugins

Plugins are off by default. Enable one in Features → Plugins; the host picks it up automatically after that — no pairing.

🌐

Internet Search

Web search and page fetch for grounded answers. When a question needs the live web, the host calls the plugin — the answer still lands in your on-device chat.

web_search — Google, DuckDuckGo and Qwant engines, with app-gate walls filtered out so the observation is real article text, not a social app's "open in app" wall. The search engine result page stays in its own tab as proof.
browser_fetch — fetches one URL on-device in a visible, tabbed mini-browser: plain HTTP + HTML→text, and pages that need JavaScript open in the WebView tab, with its own browser settings.
A bot wall opens as a visible tab with a notification — solve the challenge, then ask again. Wipe on close is on by default and clears cookies, site data and cache when the browser closes.
By default you approve each search — Approve, Edit or Skip — and automatic approval is optional. Fetched pages can be attached to chat, several at once, or imported into Files; every request is visible in the plugin's selectable log screen.

Apache-2.0 · dependencies OkHttp (Apache-2.0) and jsoup (MIT) — no trackers, no analytics.

LiveCast

Your phone becomes a projector. Kenosis AI transcribes a lecture, a talk, a meeting — live, in real time — and LiveCast shares that transcript with any device on the same Wi-Fi. Open a link or scan a QR code and follow along on a laptop, a tablet, or a second phone. The projector page follows the live transcript, and periodic digests summarize the talk as it goes.

The main app does all the work — it listens and transcribes on-device, fully offline, using the microphone permission you granted it and the Whisper model you downloaded. This plugin simply serves what the main app already produced, on your own network: nothing is uploaded anywhere, and the connection exists only while the session runs.

Same-Wi-Fi trust only: the page has no TLS and no password — anyone on your network with the URL can read the transcript while a session runs. Stop the session to end it. Some routers' client isolation can block the connection entirely.

Apache-2.0 · networking NanoHTTPD (BSD-3-Clause) — no trackers, no analytics.
Beta in Kenosis AI 1.9.37 — enable it in Features → Plugins, then open the LiveCast tile in the drawer.
