Kenosis AI plugins

Kenosis AI ships without the Android INTERNET permission — Android itself blocks its network access. Plugins are separate apps that add optional abilities: the host discovers them on the same device and talks to them over a local binder — never a socket, never a server.

Every plugin is open source and shows exactly what it does. Uninstall the plugin, and the host carries on fully offline.

How plugins work

One hard architecture rule: only one component of the ecosystem is ever allowed to touch the network.

1

The host stays offline

Kenosis AI has no INTERNET permission. Android itself enforces the isolation — it works in airplane mode, forever.

2

A plugin binds locally

The host discovers a plugin app on the device and binds it over a local AIDL binder. The open contract is one small file, identical in both apps.

3

You see everything

A plugin is an app of its own, with its own screen and a live log of every URL it fetched. Nothing hidden, nothing unlogged.

Internet Search

Web search and page fetch for grounded answers. When a question needs the live web, the host calls the plugin — the answer still lands in your on-device chat.

web_search — Google, DuckDuckGo and Qwant engines, with app-gate walls filtered out so the observation is real article text, not a bot wall.
browser_fetch — fetches one URL on-device: plain HTTP + HTML→text, with a hidden WebView fallback for pages that need JavaScript.
Every fetch is visible in the plugin's own log screen.

Apache-2.0 · dependencies OkHttp (Apache-2.0) and jsoup (MIT) — no trackers, no analytics.
